# Home Presence Bot

Telegram-бот для Tenda AC10 з прошивкою `V16.03.62.11_multi`. За замовчуванням кожні 60 секунд читає список підключених клієнтів виключно через API роутера, визначає присутність за MAC-адресою й зберігає історію в SQLite. Інтервал задається змінною `POLL_SECONDS` (ціле число від 30 до 300). Для роботи потрібні доступ Docker-хоста до локального вебінтерфейсу Tenda і вихід до Telegram.

## Налаштування

1. Скопіюйте `.env.example` у `.env`. Вкажіть `TENDA_URL` з фактичною адресою вебінтерфейсу Tenda, наприклад `http://192.168.0.1`, і заповніть `TELEGRAM_BOT_TOKEN` та `ADMIN_USER_IDS`.
2. Додайте `MEMBER_USER_IDS` для мешканців і `ALLOWED_GROUP_IDS` для спільних груп. Кілька ID розділяйте комами. Приватний chat ID дорівнює Telegram user ID. У приватному чаті кожен одержувач має надіслати боту `/start`.
3. Передайте пароль вебінтерфейсу Tenda як змінну `TENDA_PASSWORD` у середовище Docker. У терміналі Bash введіть його без відображення. У Portainer задайте `TENDA_PASSWORD` у **Environment variables** наявного або нового стека.

```bash
read -rsp "Пароль вебінтерфейсу Tenda: " TENDA_PASSWORD
printf '\n'
export TENDA_PASSWORD
```

Маршрути **Адмін**, **Нові MAC** і **Візити гостей** задаються через `/settings` або змінні `ADMIN_CHAT_ID`, `DISCOVERY_CHAT_ID`, `GUEST_CHAT_ID`. Без явного маршруту використовується приватний чат адміністратора з найменшим ID. Адмін отримує прихід і вихід гостя, а окремий чат візитів також отримує прихід. У `/settings` кнопка **Дізнатися ID цього чату** показує chat ID дозволеного чату.

## Запуск і оновлення без втрати даних

Залиште назву Compose-проєкту `home-presence`, том `home_presence_db` і шлях `/data/presence.sqlite3`. У цьому томі зберігаються пристрої та їхні власники, гості, історія, налаштування Telegram і черга сповіщень. Версія 4 відкриває наявну базу без зміни схеми. Підтверджений стан зберігається; перші нові перевірки заново підтверджують кандидатів на вихід або повернення. UID/GID контейнера залишаються `10001:10001` для сумісності з правами наявного тому.

У `.env` або Portainer задайте `BOT_IMAGE=home-presence-bot:4` і `POLL_SECONDS=60` (або приберіть їхні старі значення, щоб застосувати типові). Збережіть `POSITIVE_CHECKS=2`, `OFFLINE_SECONDS=300`, чинні `TENDA_URL`, `TENDA_PASSWORD` і налаштування Telegram. Застарілі змінні попереднього джерела даних видаліть із середовища стека.

```bash
docker build -t home-presence-bot:4 .
```

Для наявної інсталяції створіть копію SQLite перед заміною контейнера. Команда `backup` SQLite включає актуальні транзакції з WAL.

```bash
umask 077
docker volume inspect home_presence_db >/dev/null &&
  docker run --rm --mount type=volume,source=home_presence_db,target=/data \
    home-presence-bot:4 python -c '
import sqlite3, sys
from pathlib import Path
with sqlite3.connect("file:/data/presence.sqlite3?mode=ro", uri=True) as source:
    with sqlite3.connect("/tmp/presence-backup.sqlite3") as target:
        source.backup(target)
sys.stdout.buffer.write(Path("/tmp/presence-backup.sqlite3").read_bytes())
' > "presence-backup-$(date +%Y%m%d-%H%M%S).sqlite3"
```

Оновіть сервіс на тому самому Docker-хості. `up -d` підміняє контейнер зі збереженням підключеного тому. Під час оновлення збережіть том `home_presence_db`, зокрема не використовуйте `down -v`. [Docker Compose up](https://docs.docker.com/reference/cli/docker/compose/up/)

```bash
docker compose -p home-presence config --quiet
docker compose -p home-presence up -d --no-deps bot
docker compose -p home-presence ps
docker compose -p home-presence logs --tail=30 bot
unset TENDA_PASSWORD
```

Для одного токена Telegram використовуйте один запущений екземпляр бота.

### Portainer Stack із GitHub

Compose призначений для Docker Standalone. Спочатку зберіть `home-presence-bot:4` на тому самому Docker-хості, яким керує Portainer, із поточної гілки `main`. Наприклад, у локальній копії репозиторію на цьому хості виконайте `git pull --ff-only origin main` та наведену вище команду `docker build`. Git-стек використовує цей готовий локальний образ.

Для нового розгортання виберіть **Stacks → Add stack → Repository** і задайте:

- Name: `home-presence`.
- Repository URL: `https://github.com/shpak-d/home-presence-telegram-bot`.
- Repository reference: `refs/heads/main`.
- Compose path: `docker-compose.yml`.
- Environment variables: чинні `TELEGRAM_BOT_TOKEN`, `ADMIN_USER_IDS`, `TENDA_URL`, `TENDA_PASSWORD`, решту власних налаштувань із `.env.example`, а також `BOT_IMAGE=home-presence-bot:4`, `POLL_SECONDS=60`, `POSITIVE_CHECKS=2`, `OFFLINE_SECONDS=300`.

Для наявного Git-стека **home-presence** оновіть змінні через **Edit stack settings**, потім виберіть **Pull and redeploy**. Залиште **Re-pull image and redeploy** вимкненим для локально зібраного образу. Якщо стек створено через Web editor, оновіть його Compose у вкладці **Editor** і застосуйте **Update the stack**. Збережіть том `home_presence_db`; не запускайте другий стек паралельно з першим. [Створення стека з Git](https://docs.portainer.io/user/docker/stacks/add#option-3-git-repository), [оновлення стека](https://docs.portainer.io/user/docker/stacks/edit#pull-and-redeploy).

Після запуску відкрийте `/status`. Перевірте, що інтервал дорівнює 60 с, час останнього прийнятого списку Tenda оновлюється й стан даних актуальний. При помилці з’єднання перевірте доступ із `br-homepresence` до IP і порту роутера.

Healthcheck у Compose перевіряє контейнер раз на `POLL_SECONDS`; початковий період також дорівнює цьому інтервалу. Внутрішній нагляд оновлює heartbeat кожні 5 секунд і враховує налаштований інтервал Tenda. Він контролює роботу циклів опитування, Telegram і доставки сповіщень. Тимчасова недоступність роутера відображається в `/status`, а повторні спроби тривають автоматично.

## Пристрої та сповіщення

1. Звірте MAC телефона для домашньої Wi-Fi-мережі зі списком клієнтів Tenda. У `/unknown` відкрийте картку й виберіть **Категорія → Мій пристрій**. Для ручної реєстрації відкрийте `/devices → Додати за MAC`.
2. Укажіть назву пристрою й власника у форматі `Аня | 123456789`. Власник має бути в `ADMIN_USER_IDS` або `MEMBER_USER_IDS`.
3. Увімкніть **Моніторинг** і **Ключі**. Кнопка **Chat ID** задає одержувача нагадування. Кнопка **Повідомлення про прихід і вихід** керує звичайними сповіщеннями адміну для цього пристрою.
4. Для гостя виберіть категорію **Гість** і вкажіть ім’я. Однакове ім’я об’єднує кілька MAC одного гостя. Прихід підтверджується за першим пристроєм, який повернувся, а вихід за останнім, який підтверджено зник.

Нові MAC автоматично потрапляють у `/unknown`. Перший список у порожній базі імпортується тихо. Щоб отримати повідомлення і для нього, задайте `ANNOUNCE_INITIAL_DEVICES=true`. Для зміни MAC зареєстрованого пристрою використовуйте **MAC** у його картці, щоб зберегти історію та прив’язку.

| Команда | Дія |
| --- | --- |
| `/start` | Головне меню |
| `/home` | Підтверджені присутні пристрої |
| `/devices` | Картки пристроїв і ручна реєстрація |
| `/guests` | Гості та їхня присутність |
| `/unknown` | Нові пристрої |
| `/history` | Історія подій |
| `/settings` | Одержувачі та пороги |
| `/status` | Останнє успішне опитування й стан доставки |
| `/help` | Довідка |
| `/cancel` | Скасувати запити введення в поточному чаті |

Кнопки редагують поточне повідомлення. Для введення даних бот надсилає окремий запит, а після відповіді оновлює картку або налаштування.

## Як підтверджується присутність

- Клієнт надсилає MD5 пароля на `/login/Auth`, тримає cookie в пам’яті й отримує ключ з `/goform/stokCfg`. Відповідь `/goform/getOnlineList` розшифровується з Base64 через AES-128-CBC і PKCS7. При завершенні сесії бот входить повторно й робить одну повторну спробу опитування. Діагностика показує тип помилки без тіла відповіді, cookie чи ключа.
- Прихід підтверджується двома послідовними успішними опитуваннями (`POSITIVE_CHECKS=2`). Вихід вимагає, щоб MAC був відсутній у послідовних валідних списках щонайменше `OFFLINE_SECONDS=300`. Ці правила діють цілодобово. Допустимий розрив `max_poll_gap` дорівнює `2 × POLL_SECONDS` (120 с за замовчуванням), щоб звичайні затримки відповіді не скидали підтвердження. Більший розрив починає підтвердження заново.
- Збій API, невдала розшифровка чи некоректний список переривають послідовність перевірок. Підтверджений стан зберігається. Відлік відсутності після розриву починається зі свіжих списків.
- Після перезавантаження роутера бот продовжує спроби з інтервалом `POLL_SECONDS`. Коли Tenda знову доступна й відхиляє стару сесію, клієнт автоматично отримує нові cookie, ключ і токен маршруту та відновлює опитування.
- Нагадування про ключі надходить після підтвердженого повернення за відсутності від `max(REMINDER_ABSENCE_SECONDS, REMINDER_QUIET_SECONDS)` (20 хв за замовчуванням). Відлік іде від збереженого початку підтвердженої відсутності. Одиничне хибне виявлення телефона цей час не скидає.

Для перевірки на вашому роутері підключіть зареєстрований телефон і дочекайтеся двох опитувань. Потім вимкніть Wi-Fi на телефоні й перевірте `/home` після порогу відсутності. Для перевірки нагадування підключіть телефон знову після спливу порогу ключів.

## Локальні тести

```bash
python -m pip install -r requirements.txt
python -m unittest discover -s tests -v
```

Тести перевіряють діапазон `POLL_SECONDS`, планування і healthcheck для 30/60/300 с, підтвердження присутності та відсутності, збереження даних після повторного відкриття SQLite, нагадування, нічний режим, гостей і Telegram. Тести протоколу запускають локальну HTTP-модель роутера та перевіряють відновлення авторизації після збою й перезавантаження.
